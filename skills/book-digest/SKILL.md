# book-digest

对全书做**完整、全面**的内容总结，独立输出 `digest.md`。

与相邻 Skill 的分工：

| 文件 | 回答的问题 | 粒度 |
|------|------------|------|
| `summary.md` | 主张、概念、论证骨架是什么 | 每章一句话 |
| `reading-guide.md` | 该怎么读（精读/跳过） | 读法，不代替内容 |
| `digest.md` | **这本书每一章具体讲了什么** | 每章一篇详述 + 全书总述 |

`digest.md` 必须覆盖目录中的**每一章**（含前言/结语若有实质内容）。阅读标注里标「可跳过」的章仍要总结：完整覆盖 ≠ 建议精读。

## 前置条件

- `book-ingest` 已完成
- 必须依据 `library/parsed/` 原文或 `book-query` 检索，禁止只根据 `summary.md` 扩写

## 执行流程

1. 从解析稿抽出完整目录（章 + 主要小节）
2. **按章顺序**阅读该章正文（可用 query 按章节锚点取块，长章分段读完再写）
3. 每写完一章，对照小节清单：有未写到的小节则补写
4. 全部章写完后，写「全书总述」（综合，不是把各章首句粘贴）
5. 做覆盖检查：目录章数 = 详述章数

## 每章详述结构（缺一不可）

```markdown
### 第X章 标题

**本章主旨**：2–4 句，说明这一章要解决什么问题、结论是什么。

**内容展开**：
按本章真实小节顺序写。每个主要小节至少一段，写清：定义/主张、作者怎么论证、关键例子或数据、限定条件。不要只列小标题。

**本章要点**：3–6 条，用完整句子，可单独当笔记。
```

篇幅：每章正文（不含标题）一般 **400–1200 字**。框架章、实战章取上限；工具名录、致谢可 200–400 字，但不可只有一句话。禁止全书平均每章三句话。

## 全书总述结构（缺一不可）

放在**所有逐章详述之后**：

```markdown
## 全书总述

**这本书主要讲了什么**：400–800 字，按作者论证顺序讲清：问题 → 主框架 → 各部分如何接力 → 收束。读者只读这一节也应能向别人转述全书。

**部分与部分如何衔接**：说明篇/部分之间的逻辑（例如框架篇 → 实战篇 → 方法篇）。

**读完应记住的主线**：5–8 条，覆盖全书而非只覆盖前三章。
```

## 输出文件结构

1. 书名、作者
2. 目录（章标题列表，便于跳转）
3. 逐章详述（按原书顺序）
4. 全书总述
5. 覆盖声明：列出已覆盖的章；若某章原文缺失标 `[待核实]`

## 输出

写入 `workspace/<slug>/digest.md`。

## 禁用

- 不许用章节地图的一句话冒充详述
- 不许把 insights / 读法建议写进本章展开（那是别的文件的职责）
- 不许虚构未出现的案例、数据、人名
- 禁用词同 `constraints.yaml`
- 不确定标 `[待核实]`

## 验证

- 目录中每一章都有对应 `###` 详述
- 存在「全书总述」且不少于约 400 字
- 至少一半的章达到 400 字以上
- 每章有「本章主旨 / 内容展开 / 本章要点」
