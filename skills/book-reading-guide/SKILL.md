# book-reading-guide

为全书做**读法标注**，独立输出 `reading-guide.md`。

与 `book-summary` 的区别：summary 说明「书讲了什么」；本 Skill 说明「该怎么读」——哪章精读、哪章略读、哪段是骨架、哪段注水。

## 前置条件

- `book-ingest` 已完成（`workspace/<slug>/book.yaml` 存在）
- 向量索引已构建
- 若已有 `summary.md` 的章节地图，用作目录底稿；没有则用 `book-query` 检索目录

## 默认读者

未指定目的时，按「第一次通读、要抓住可迁移框架」标注。用户若给出目的（投资 / 转行 / 写代码 / 考证），必须按该目的重标，并在文首写明「适用目的」。

## 标签（每章必须且只能打一个）

| 标签 | 含义 | 何时用 |
|------|------|--------|
| 精读 | 慢读、核对原文、可做笔记 | 提出核心公式/原则，后文都建立在这上面 |
| 带着问题读 | 对照自己的场景选用，不必逐段抠 | 维度拆解、案例库、应用章 |
| 略读 | 扫标题与结论即可 | 重复论证、激励性铺陈、已知背景 |
| 当附录查 | 不通读，用到再翻 | 工具列表、资讯源、API/产品清单 |
| 可跳过 | 不影响抓住骨架 | 营销前言、重复鸡汤、过时产品点名、与目的无关的专题 |

禁止：全书超过一半章节标「精读」。精读章控制在 **1–4 章**。至少标出 **1 个**「略读 / 当附录查 / 可跳过」。

「毫无意义」只用于注水段判断，不要用来否定整本书；写「对抓住骨架无增量」，并给理由。

## 执行流程

1. 用 `book-query` 取目录、各章篇幅与重复主题
2. 找出全书骨架（通常 1–3 个主张，对应 1–4 章）
3. 识别注水：重复定义、励志故事、工具名录、过时产品、与主线无关的专题
4. 按标签给**每一章**打标，写「为什么」和「读到什么算过关」
5. 给出 30 分钟 / 2 小时 / 精读两套时间盒读法

## 输出结构（缺一不可）

### 1. 适用目的
一句话：默认读者 + 本标注为谁服务。

### 2. 核心骨架（必精读）
1–3 条主张 + 对应章节。这是「不读这些等于没读」。

### 3. 章节读法表
覆盖目录中每一章（含前言/结语）：

| 章节 | 标签 | 理由 | 读到什么算过关 |
|------|------|------|----------------|

### 4. 可略读 / 可跳过
列出注水或低增量部分：段落级优先（「第 X 章后半的工具名录」），不要只写章名。

### 5. 时间盒读法
- 30 分钟：只读骨架章的哪些小节
- 2 小时：骨架 + 带着问题读的哪几章
- 精读路径：顺序与配套练习（若有实验/案例）

### 6. 按目的分流（可选但推荐）
2–3 个常见目的，各给「多读 / 可砍」差异。无把握标 `[待核实]`。

## 输出

写入 `workspace/<slug>/reading-guide.md`。

## 禁用

- 不许每章都精读
- 不许只复述章节地图而不给标签
- 不许虚构「作者说这一章可以跳过」；跳过判断是读法建议，须写明是标注者判断
- 禁用词同 `constraints.yaml`

## 验证

- 上述 1–5 节标题全部出现
- 章节读法表行数 = 目录章数（含前言/结语若存在）
- 精读章 1–4 个
- 至少 1 个非精读标签
- 每条判断能回溯到章节名
