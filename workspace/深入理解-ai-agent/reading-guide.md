# 阅读标注：深入理解 AI Agent

## 1. 适用目的

默认读者：已有 Python / LLM 使用经验，要把 Agent 从 Demo 做到可维护产品；用本书当地图，而不是当论文综述。

## 2. 核心骨架（必精读）

1. **Agent = LLM + 上下文 + 工具；生产形态是 Model + Harness（约束 / 验证 / 纠正）** — [第1章]
2. **没有评估就没有进步** — [引言 + 第6章的原则部分]
3. **Coding + 文件系统是通用 Agent 内核，不是堆垂直 API** — [第5章开篇原则，细节对照仓库实验]

不读第 1 章，后面 MCP、多 Agent、后训练都会散掉。

## 3. 章节读法表

| 章节 | 标签 | 理由 | 读到什么算过关 |
|------|------|------|----------------|
| 引言 | 带着问题读 | 「没有评估就没有进步」是骨架句；其余背景可扫 | 能复述为什么感觉变好了不等于真变好 |
| 第1章 入门 | 精读 | 公式、ReAct、Harness 五要素是全书坐标系 | 能画出 ReAct 循环，并给自己的 Agent 列出约束/验证/纠正 |
| 第2章 上下文工程 | 带着问题读 | Cache/压缩/Skills 是架构问题；未做长上下文可后置细节 | 知道何时压缩、何时开子 Agent，而不是无脑加长 prompt |
| 第3章 记忆与 RAG | 带着问题读 | 已有 RAG 项目可对照；从零做检索再精读分块与混合检索 | 能说出记忆层次与「检索 ≠ 长推理」 |
| 第4章 工具 | 带着问题读 | MCP/异步决定上限与可靠下限；接工具时再抠协议细节 | 能检查参数保真，并用致命三要素审工具组合 |
| 第5章 Coding Agent | 精读 | 元能力判断；案例（Manus/OpenClaw）可略，原则要留下 | 认同「先文件系统+代码执行」并对照自己的工具集 |
| 第6章 评估 | 精读 | 方法论不过时；具体基准名会变，原则（任务集/Judge/显著性）要留下 | 能为当前 Agent 写出 ≥10 条可自动判分任务 |
| 第7章 后训练 | 可跳过 | 不做 SFT/RL 则对产品 Agent 无增量；有训练岗位再读 | 无（默认路径） |
| 第8章 自我进化 | 带着问题读 | Skills/经验外置有用；实现细节跟仓库走 | 能区分「改权重」与「改外部知识/工具」 |
| 第9章 多模态与实时 | 可跳过 | 不做语音/Computer Use/机器人则与主线无关 | 无（默认路径） |
| 第10章 多 Agent | 略读 | 分工与上下文隔离有概念价值；编排框架迭代快 | 能说出共享 vs 隔离上下文各适合什么 |

## 4. 可略读 / 可跳过

- **具体产品名、某版 MCP/Skills 用法**：时效短，对抓住骨架无增量；以官方仓库实验为准。
- **第7章后训练整章**（非训练岗）：原则已在第1、6章覆盖。
- **第9章多模态专题**：与「文本 Agent 上生产」主线无关。
- **第5章过长案例叙事**：留下「代码可作思考/约束/适配器/自举」，故事可扫。
- **重复定义 Agent 公式的段落**：第1章读透后，后文再出现视为回声。

## 5. 时间盒读法

- **30 分钟**：第1章公式 + Harness 三层 + 引言里评估那一句。合上书后给自己的系统写三条约束/验证/纠正。
- **2 小时**：第1章 + 第6章评估原则（跳过基准安装）+ 第5章开篇「Coding 内核」+ 扫第4章致命三要素。
- **精读路径**：第1章 → clone `bojieli/ai-agent-book` 跑 1 个最小实验 → 第6章搭 10 条回归任务 → 第2/4/5 章按自己缺口选读 → 第7/9 章默认不读。

## 6. 按目的分流

| 目的 | 多读 | 可砍 |
|------|------|------|
| 做生产文本 Agent | 第1、2、4、6章 | 第7、9章 |
| 做 Coding Agent | 第1、5、6章 + 仓库实验 | 第9、10章可后置 |
| 做模型训练 | 第6、7章 | 第9章；第10章可后置 |
| 只想建立概念 | 第1章 + 第6章原则 | 第2–5、7–10 的实现细节 |
