## 引言

**本章主旨**：用开源书 + 实验把 Agent 从 Demo 讲到生产。核心判断：**没有评估，就没有进步。** 并预告十章如何展开公式 Agent = LLM + 上下文 + 工具。

**内容展开**：作者背景偏系统研究与生产 Agent。全书结构：第 1 章公式与 Harness；第 2 章眼睛（上下文）；第 3 章跨会话记忆与 RAG；第 4 章手脚（工具）；第 5 章 Coding 内核；第 6 章评估；第 7 章改权重；第 8 章不改权重的进化；第 9 章语音/GUI/机器人；第 10 章多 Agent。阅读建议与前置知识（Python、LLM 使用）写在引言后部。评估被放在与模型同等重要的位置：一次改动是真变好还是运气，要靠任务集分辨。

**本章要点**：先建立「评估闭环」意识，再进入各章机制。

## 第1章 AI Agent 入门

**本章主旨**：Agent = LLM + 上下文 + 工具（大脑/眼睛/手脚）。生产形态再写成 Model + Harness，Harness = 上下文 + 工具 + 约束 + 验证 + 纠正。工作循环是 ReAct。

**内容展开**：

LLM 是决策内核（预训练知识 + 后训练策略）。上下文是每个决策点能看到的全部信息，不是一段 prompt 字符串。工具是能做的一切：API、Skills、写代码、子 Agent、对用户沟通、响应事件。可选对照 RL：策略 / 观察 / 动作。

ReAct：思考→行动→观察，轨迹是不断追加的 user/assistant/tool 消息。书中用多轮工具调用伪代码说明：框架执行工具、把结果写回轨迹、模型再看完整轨迹。

Demo 能跑仍会幻觉、选错工具、出错无法恢复。Harness 不是第三套公式，而是给「上下文+工具」加三层外壳。退款例子：无 Harness 会编造已退款；有 Harness 则政策进上下文、query_order / process_refund、金额约束、查库验证、超时重试。隐喻：无 Harness 的模型像脱缰野马。模型升级是共享红利，护城河在 Harness（上下文策略、工具、评估、安全）。另有编排光谱（工作流→自主 Agent）与安全铺垫，细节在后续章展开。

**本章要点**：

- 最小公式跑 Demo；扩展公式跑生产。
- 同一模型有无 Harness，结果可以完全不同。
- 调试时要会读 ReAct 轨迹。

## 第2章 上下文工程

**本章主旨**：上下文决定能力上限。要从 API 消息结构、KV Cache、提示词、Skills、状态栏、压缩与隔离来设计，而不是把一切塞进超长窗口。

**内容展开**：

2.1 上下文 = 决策可见的全部信息。2.2 用 Chat API 的角色消息理解「模型实际看到什么」。2.3 KV Cache 友好：稳定前缀、少扰动系统提示，才能吃到缓存与 Prompt Cache。2.4 系统提示工程。2.5 动态提示与 Agent Skills：按需加载说明书，而不是永远全量。2.6 状态栏用元信息管理轨迹。2.7 压缩：超阈值时摘要或丢弃，而不是无限加长。原则：子 Agent 隔离往往优于把所有细节堆进父上下文。本章小结把这些收成架构问题：上下文学习更像检索而非无限长推理。

**本章要点**：

- 先问 Cache 是否友好、何时压缩、何时开子 Agent。
- Skills 是上下文的模块化，不是又一个聊天技巧。

## 第3章 用户记忆和知识库

**本章主旨**：把「当前会话看见什么」延伸到跨会话的用户记忆，以及用 RAG 从外部知识取证据。

**内容展开**：

3.1 用户记忆分层（偏好、事实、习惯等），与第 8 章「经验策略」区分：记忆回答「用户是谁」。3.2 RAG 管道：分块、嵌入、检索、写入上下文；混合检索（向量 + 关键词）是常见补强。3.3 超越扁平文本：GraphRAG、RAPTOR、层级组织；Agentic RAG 让模型决定何时检索、检索什么。扁平长文本检索解决不了「需要结构」的问题。

**本章要点**：

- 记忆 ≠ RAG：一个记人，一个记世界知识。
- 检索质量有上限，组织方式会改变上限。

---

## 第4章 工具

**本章主旨**：工具质量决定能力上限；异步架构决定真实世界能否可靠运行。底线是参数保真：模型看见的世界与工具操作的世界不能系统性偏离。

**内容展开**：

五类工具：感知、执行、协作、事件触发、用户沟通。设计原则后进入 MCP 与工具选择：接入越多，组合出的攻击面越大。感知/执行/协作分节讲接口形态。事件驱动异步 Agent：长任务、打断、虚拟身份等（书中结合 OpenClaw 一类案例）。致命三要素（与第 5 章呼应）：同时具备访问私有数据、暴露于不可信内容、能对外通信，即完整攻击闭环。本章小结重申工具上限与异步下限。

**本章要点**：

- 先保证参数与状态一致，再堆新服务器。
- MCP 接入前用致命三要素做组合审查。

---

## 第5章 Coding Agent 与代码生成

**本章主旨**：Coding + 文件系统是通用 Agent 的内核，不是「再封装一批垂直 API」。

**内容展开**：

5.1 以 Manus / OpenClaw 等说明：能读改文件、能跑代码，就能适配未知环境。Harness 在此具体化为沙盒、权限、循环预算。5.2 代码作为元能力：思考工具、把业务约束写成可执行规则、系统适配器、生成式 UI、自举新 Agent 与新工具。案例可扫，原则要留。安全与「致命三要素」在会执行代码时被放大。

**本章要点**：

- 通用 Agent 优先投资文件系统 + 受控执行。
- 代码既是动作也是约束的载体。

---

## 第6章 Agent 的评估

**本章主旨**：评估把「感觉变好了」变成可证伪的改进。覆盖环境、任务集、指标、LLM-as-a-Judge、选型、统计显著性、可观测性、从 benchmark 到生产评估与仿真。

**内容展开**：

先给一个具体评估示例，再分自动评估环境（工具调用型 vs 人机交互型）。任务集设计决定你到底在测什么。指标体系与自动化方法（含 Judge）之后，讲用评估驱动选模型，而不是看榜单叙事。统计显著性避免小样本运气。可观测性让失败可调试。从公开 benchmark（Terminal-Bench、SWE-bench、GAIA 等在书中被对齐）走到内部回归集与生产基础设施。仿真环境作为通向第 7 章后训练的桥梁。引言那句在此落地：没有评估就没有进步。

**本章要点**：

- 改 prompt 或工具前先有可自动打分的任务。
- 外部榜与内部回归是两件事。

## 第7章 模型后训练

**本章主旨**：SFT 偏记忆「照样学样」，RL 偏泛化与工具调用内化。对不做训练的读者可当选读，但要知道「改权重」与第 8 章「不改权重」的边界。

**内容展开**：

预训练 / SFT / RL 三阶段。7.2–7.3 标为可选：经典 RL 与预训练基础。SFT 与 RL 的选用：何时背流程、何时要探索。单轮 RL 看记忆 vs 泛化。RLHF、算法比较。作者强调数据与环境往往比算法更关键。多轮信用分配与奖励设计是 Agent 特有难点。RL 学习工具调用、样本效率、实践图景。语音「该不该收话」等例子用来说明标签与奖励，而不是模型结构本身。

**本章要点**：

- 后训练改的是策略权重。
- 奖励与环境错误会稳定地训练出错误行为。

---

## 第8章 Agent 的自我进化

**本章主旨**：在不修改模型权重的前提下变强：从经验抽策略、发现与创造工具、把知识外置为 Skills/工作流。

**内容展开**：

上下文学习更像检索，不会自动把一次成功变成权重。用户记忆只沉淀「用户是谁」。三种范式对照：后训练 vs 记忆 vs 本章的策略外置。从经验中学习、主动工具发现、从使用者到创造者（写代码生成工具）。与第 5 章 Coding 内核闭合：自举新能力不必每次 SFT。

**本章要点**：

- 进化可以发生在 Harness 与文件系统，而不在 GPU。
- 录制成功轨迹 → 可复用技能，是具体路径之一。

---

## 第9章 多模态与实时交互

**本章主旨**：感知与行动从文本扩展到语音、GUI、机器人；实时性迫使架构在级联、端到端 Omni、思考分离与统一之间做取舍。

**内容展开**：语音三种范式（级联流水线、端到端、混合）。更像人的 TTS。Computer Use 作为 GUI Agent。机器人 VLA 与 sim-to-real（回指第 6 章仿真）。不做语音/机器人的读者，本章对文本 Agent 主线增量有限。

**本章要点**：实时系统的核心约束是延迟与打断，不是又一个 prompt。

---

## 第10章 多 Agent 协作

**本章主旨**：多 Agent 不是公式之外的新物种：关键变量是上下文共享还是隔离（第 2 章「隔离优于压缩」的系统版）。

**内容展开**：分类框架；何时真正优于单 Agent（真分工 vs 假装人多）。共享上下文协作 vs 不共享。失败模式。Agent 社会作为远景。乱用多 Agent 会复制上下文爆炸与责任不清。

**本章要点**：先证明单 Agent + 子任务隔离不够用，再加第二个 Agent。

---

## 后记

**本章主旨**：回到公式。八到十章是三支柱的组合应用。提出「两朵乌云」：流式实时与持续学习仍未收口；模型与 Agent 将共同演进。

**本章要点**：架构原则应穿越具体模型版本；点名产品会过时。

---

## 全书总述

**这本书主要讲了什么**：

李博杰把 Agent 收成一句可执行的话：决策在 LLM，看见什么由上下文工程决定，能改变世界靠工具。ReAct 把三者连成轨迹。只靠这三件可以做 Demo；生产必须把约束、验证、纠正写成 Harness，否则幻觉和不可恢复会变成产品事故。第 2–4 章分别深挖眼睛、记忆/知识、手脚（含 MCP 与异步、安全横切）。第 5 章主张：文件系统加代码执行是最通用的手脚，垂直 API 堆叠替代不了元能力。第 6 章给出科学迭代：任务集与显著性，而不是感觉。第 7 章改权重，第 8 章改外部记忆与工具，二者不要混。第 9–10 章把同一公式推向实时多模态和多 Agent，并提醒共享上下文的代价。读者若做生产文本 Agent，主线是 1–2–4–6；做 Coding Agent 再加重第 5 章与仓库实验。

**部分与部分如何衔接**：第 1 章立公式 → 2/3 扩眼睛与长期知识 → 4/5 扩手脚与元手脚 → 6 给度量 → 7/8 给两条变强路径 → 9/10 给更复杂环境。

**读完应记住的主线**：

1. Agent = LLM + 上下文 + 工具。
2. 生产 = Model + Harness（约束/验证/纠正）。
3. 上下文是架构问题（Cache、压缩、隔离）。
4. 工具要保真，异步才能跑长任务。
5. Coding + 文件系统是通用内核。
6. 没有评估就没有进步。
7. 改权重与改 Harness 是两条进化线。
8. 安全（致命三要素）是横切约束。
