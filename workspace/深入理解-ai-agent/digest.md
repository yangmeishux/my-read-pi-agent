### 引言

**本章主旨**：作者要把 Agent 设计从“感觉驱动”变成“原则驱动”：不只跑通 Demo，而要讲清每个架构决策的取舍。全书只用一句话钉死公式——**Agent = LLM + 上下文 + 工具**（大脑 + 眼睛 + 手脚；学术上对应 Policy / Observation Space / Action Space）。成书背景、Pine 长流程实战、全书三部分结构和阅读路径，都为后面十章提供坐标。

**内容展开**：

**成书与 whisper coding。** 材料来自 2025 年 8–10 月图灵《AI Agent 实战营》讲稿。作者用 Pine 语音 Agent 做口述协作：口述提纲 → 调研 → 初稿 → 结合学员反馈打磨。语音带宽约是打字的四倍，书既讲 Agent，也是 Agent 参与做成的作品。

**行业坐标。** 自 DeepSeek R1 起，领域进入工程落地深水区：模型侧用 Agentic RL 把工具调用训进参数；产品侧 Manus、Claude Code、OpenClaw 把“代码生成 + 文件系统”推到主流。Skill、harness、loop engineering 等名词是**实践在前、命名在后**——头部团队早就在这么做，Anthropic 等人再提炼成原则。等名词流行再动手，已经慢了一步。

**Pine 倒逼出的原则。** 作者作为 Pine AI 首席科学家，做能自主与真人交互、独立处理涉金钱长程任务的通用 Agent（打电话协商账单、退款、取消订阅）。动辄几十轮、出错即真金白银。早于流行名词，他们已用动态加载提示词压提示膨胀、用命令行执行器压工具列表膨胀、用系统状态栏补环境与时间感知；用类似 Claude Code 的方法处理工具幻觉、危险与越权；用提议者-审核者（proposer-reviewer）防止过早宣称完成。赶在名词之前有两点：一是能力上限极高的真实业务与持续反馈；二是评估——没有评估就没有进步（第六章专论）。

**Sutton 与自举。** Richard Sutton 把宇宙演化推到“设计实体 / 智能体”阶段：Agent 能通过生成代码自举与自我进化。本书使命是掌握这种创造的原则。

**全书结构（三部分）。** 第一章是基础。第二至七章依次展开三大支柱：上下文（第二、三章）、工具（第四、五章）、模型（第六、七章：评估与后训练）。第八至十章是进阶：自我进化、多模态实时交互、多 Agent 协作。引言对十章各给一段预告：ReAct、三种学习范式、编排光谱、KV Cache 与 Skills、记忆与 RAG、MCP 与异步、Coding 内核、评估闭环、SFT/RL、经验外部化、语音/Computer Use/VLA、协作分类与 Agent 社会。

**如何阅读。** 开发者建议顺序通读，第一至五章加第六章不可跳过；时间紧优先第一、二章（KV Cache 原理可先记三条结论）；关心训练则读第七、六章并先读一、二章。实验按星级标难度，代码在 https://github.com/bojieli/ai-agent-book。术语约定：reasoning 译“思考”，inference 译“推理”，固化复合词除外。

**前置知识。** 必需：Python、用过 ChatGPT/Claude 一类产品、至少一款 AI 编程工具（本身就是 Coding Agent）、命令行/Git/JSON/REST。推荐：第七章机器学习基础；2–3、7 章线性代数与概率直觉；4、9 章 Web；2、7 章 Transformer（可互补《图解大模型》）。除第七章外数学门槛低。

**致谢。** 图灵编辑与实战营学员、国科大刘俊明老师与同学、Pine 同事、业界朋友、家人（尤其孟佳颖）。

**本章要点**：

1. 公式贯穿全书：Agent = LLM + 上下文 + 工具，缺一不可。
2. 原则来自长流程高风险实战，不是名词驱动。
3. 十章按“基础 → 三支柱 → 进阶应用”组织。
4. 评估与极高能力上限的业务，是赶在流行名词之前动手的条件。

### 第1章 AI Agent 入门

**本章主旨**：用 Cursor、Deep Research、Manus、豆包、Pine 等产品说明：现代 Agent 不是一问一答，而是规划、调工具、按反馈改策略。核心公式在实现层、直觉层、学术层对齐；ReAct 把三者串成循环；生产级差异在 **Harness**（约束、验证、纠正），而不是再堆一层编排框架。

**内容展开**：

**1.1 现代 Agent = LLM + 上下文 + 工具。** LLM 是决策内核（预训练知识 + 后训练策略）；上下文是每个决策点能看到的全部（环境、记忆、知识、状态、进展）；工具是能做的一切（API、Skills、写代码、子 Agent、沟通、响应事件）。表格把 Cursor / Deep Research / Manus / 豆包 / Pine 映射到感知、行动与策略。共同点：开放动作空间、可内部思考、可持续交互。

**1.1.1 工具：手脚。** 五类：感知（搜、读文件、API）、执行（改世界）、协作（子 Agent / 人）、事件触发（邮件、定时、Webhook——Agent 注册、外部驱动）、用户沟通。工具调用四步：声明 → 模型决定调哪个、传什么 → 执行结果进上下文 → 再决策。尽量通用：Python 解释器优于专用计算器，文件系统优于专用日志工具。MCP 让接入更像装插件，设计原则不过时。接口不清、错误处理差、权限过宽，分别导致乱用、死锁、不可挽回。

**1.1.2 LLM：大脑。** 解析真实意图、拆步骤、决定是否调工具。内部思考不改环境但提升行动质量，依赖预训练沉淀的规则。零样本泛化与少样本适应是直接体现。“模型即 Agent”：后训练把工具调用内化，但模型越强，Harness 越关键——缰绳不是限制奔跑，而是把力量导向可靠执行。三种学习：后训练改权重（永久、贵、慢）；上下文学习靠注意力临时适配（会话结束即消失，更像模式匹配）；外部化学习把流程写成知识库与可执行工具（持久、可验证）。第八章比较协同。

**1.1.3 上下文：眼睛。** API 上五块：系统提示词（岗位说明书，含记忆与环境注入）、工具定义、用户消息（可含 RAG）、助手消息（思考 / 文本 / tool_calls 不必同时出现）、工具结果。前两项静态前缀，后三项动态轨迹。实验 1.1 消融：去掉工具定义则丧失行动；缺工具结果则同一工具死循环；剥思考则决策自相矛盾；无历史则失忆重跑。系统提示词不作消融，否则连角色都没有。

**1.1.4 ReAct。** 名称只有 Reason + Act，实际是想→做→看的循环。多币种收入汇总：第一轮并行 convert_currency，第二轮 code_interpreter，第三轮最终答案。上下文 = 静态前缀 + 轨迹；每次调用都是无状态的，框架必须回传完整历史。轨迹可解释、可调试，也可进知识库或 RL。实验用不同模型驱动同一循环。

**1.2 Harness 工程。** Demo 公式 LLM+上下文+工具能跑；生产要补约束、验证、纠正。展开式：Agent = Model + Harness，Harness 核心仍是上下文+工具加三层外壳。退款例子：无 Harness 则编造退款；有则政策进提示、调 query_order/process_refund、金额校验、库状态确认、超时重试。Claude Code 里大部分代码是保障而非工具本身：流程状态、多层压缩、权限分类、熔断器、错误恢复。行业从“能做事”转向“可靠地做事”。

**1.2.1 范式演进。** 软件工程 → 提示工程 → 上下文工程 → Harness 工程，层层包含。模型能力趋近后，优势在模型外。LangChain 在 Terminal Bench 2.0 上同一模型靠 Harness 从 52.8% 升到 66.5%；OpenAI 团队用 Harness 把开发速度提到约 10 倍量级。

**1.2.2 五功能原则。** 上下文：信息充分性。工具：接口清晰。约束：故障安全默认关闭。验证：只看结构化数据，防提示注入操纵自由文本。纠正：确认无法恢复前不暴露中间态。对应后文第二至六章。

**1.2.3 有效 Agent 三原则（Anthropic）。** 保持简单；保持透明；设计好 ACI（从 Agent 视角防呆，Poka-yoke）。模糊接口会被模型放大成系统性错误。

**1.2.4 选模型。** 不荐版本，讲方向：御三家侧重不同；国内豆包延迟、Kimi Agent、Qwen/DeepSeek 成本与可定制；闭源能力 vs 开源合规。绝大多数 Agent 需要思考模型；另看输出速度（多轮放大延迟）和多模态。选型必须在自己任务上测（第六章）。

**1.2.5 编排。** 先单次 LLM，再固定工作流，最后才自主 Agent——用延迟和成本换性能要谨慎。工作流路径由代码写死，安全面限在节点内，难覆盖未预设情况。自主 Agent 即 ReAct 循环，退出条件含任务完成、final_answer、无工具调用、最大轮次、错误超限；适合 SWE-bench、Computer Use、研究。实践常混合（如 n8n）。框架表对比 OpenAI Agents SDK、Claude Agent SDK、LangChain/LangGraph、n8n、Dify、CrewAI、OpenClaw：选框架看能否以最小抽象让你做业务，不看复杂度。

**1.2.6 护栏。** 输入侧：相关性/安全分类器、审核、规则（越狱 vs 提示注入：前者用户自己绕过，后者经外部数据间接操纵）。执行侧：工具风险评级。输出侧：PII、品牌一致性。人工干预：失败阈值与高风险操作。细节分散在二、四、五章。

**1.2.7 本书即 Harness 指南。** 表把二至十章映射到 Harness 功能与横切安全。Anthropic 长时 Agent：初始化 Agent 与执行 Agent 用交接制品对抗上下文耗尽与过早完成。

**1.3 本章小结。** 眼睛往往是决定性因素；Harness 是竞争力；编排从简到繁；安全是架构问题。下一章进入上下文工程。

**本章要点**：

1. Agent = LLM + 上下文 + 工具，对应大脑、眼睛、手脚。
2. 上下文 = 静态前缀 + 轨迹；ReAct 靠追加轨迹推进任务。
3. 生产公式是 Model + Harness：约束、验证、纠正决定可靠性。
4. 三种学习时间尺度不同：后训练、上下文学习、外部化学习互补。
5. 编排遵循从简单到复杂；护栏分层，人在回路处理高风险与失败阈值。

### 第2章 上下文工程

**本章主旨**：Agent 只能基于看见的信息决策，能力上限往往不在参数量而在上下文质量。本章从 API 消息结构出发，把“上下文就是消息列表”钉死，再讲 KV Cache 友好设计、系统提示与提示注入、Skills 渐进披露、状态栏蒸馏、压缩与“隔离优于压缩”。

**内容展开**：

**2.1 能力上限。** 天才工程师不懂你们的架构、债务与规范，就发挥不出来。Coding Agent 最低需要实时代码、流程规范、环境信息。上下文工程首先是技术问题，更是组织问题：隐性知识锁在老员工和私聊里，Agent 无计可施。远程友好、文档驱动的团队（如 Linux 内核）天然对 Agent 友好。翁家翌：“人和模型一样，最重要的是 Context。”

**2.2 API 结构。** 四角色：system / user / assistant / tool（用 tool_call_id 配对）；tools 是独立字段。每次调用无状态，必须带完整 messages。带工具的多轮：模型只决策，框架执行；第二次请求原样放回第一次的 assistant。最小实现就是 while：有 tool_calls 则执行并继续，否则退出。后续所有技巧都是在优化这个列表。静态前缀不动利于缓存，轨迹可压缩。实验 2-1：0.6B 本地模型也能可靠工具调用；流式里思考→文本→工具有固定顺序；可并行 tool_calls。

**2.3 KV Cache 友好设计。** 前缀改一个字符，缓存全废。客服 Agent 把当前时间戳塞进系统提示，TTFT 从约 0.5s 到 3–5s，账单翻倍。三条必须记住的结论：系统提示和工具定义一旦确定不要改；动态信息追加末尾；用标准 API，不要自行拼角色纯文本（破坏训练格式与多步思考，缓存只认字节序列）。实验 2-2：注意力 Q/K/V；热力图因果三角；Attention Sink（softmax 强制权重和为 1）；位置偏好（头尾易记、中间易丢）。Chat Template 把 JSON 变成特殊标记线性 token；把 tool 结果标成 user 会误触发“换话题”清思考。KV 与 Prompt Cache 是两层：单次推理内 vs 跨请求；Anthropic 需 cache_control，OpenAI 自动前缀缓存。生产上缓存是架构约束：缓存边界决定提示排列；子 Agent 必须与父 Agent 字节级对齐才能蹭缓存；工具结果替换字符串首次冻结。研究延伸（可跳过）：prefill 像做笔记，KV 或许可编辑/组合，当前生产仍守三条铁律。错误模式：动态系统提示、动态用户配置、工具定义重排、滑动窗口丢工具结果、纯文本格式化。

**2.4 提示工程。** 检验标准：聪明新员工读完是否知道怎么做。语气：MUST/NEVER 比 please 更抓注意力，滥用则稀释。结构：XML 语义 + Markdown 层次。组织：流程驱动的 SOP 优于上百条无序规则；消融里打乱组织成功率降超 30%。业务规则要细到可执行（Pine 计费：提成仅限谈判降现有账单，退款/取消绝不走百分比）。产品定规则，工程师编码格式。Few-shot 适合难用规则描述的风格；示例必须字节级稳定，两三个覆盖边界胜过十个雷同。工具定义要写边界、例子、批调用、工具间关系。提示注入：外部内容劫持指令，Agent 有工具后危害远超聊天机器人。防御：来源标记、严格角色、输入清洗；Skills 与状态栏也是注入面。上下文层只能降成功率，执行层沙盒在四、五章。

**2.5 Skills。** 提示膨胀浪费 token、稀释注意力。渐进披露：YAML 元数据常驻（description 要写成 Use when / Don’t use when，反例决定路由）；需要时加载 SKILL.md；再按引用读细则；可捆绑脚本与模板。实现三方式：注入 system 效果最好但破坏缓存；当普通文件读不影响缓存但指令遵循弱；生产（Claude Code）：元数据以 user-role meta 增量发到末尾，完整内容用专用 Skill 工具加载——模型对“自己刚调的工具输出”执行倾向更强。Skills + 少量通用工具，避免工具定义撑爆前缀。

**2.6 状态栏。** 注意力擅长检索不擅长一次前向里归纳。电话上限 3 次，模型常数错。把“第 3 次呼叫”写成显式状态，错误率大降。论文 Distill, Don’t Retrieve：弱模型准确率可涨 40–54 个百分点；强模型思考 token 可砍八九成。经验：用代码维护状态，不要让 LLM 批量统计历史；删原文前确认状态栏覆盖会被问到的维度；把状态栏准确率当生产指标，模型几乎无条件相信它。构成：TODO、侧信道（时间/地点）、环境状态、Skills 清单。位置：借用 user 槽位追加末尾，不改 system。更新：每轮替换（上下文干净，末尾缓存失效）vs 持久追加（缓存友好，旧状态累积）。实验 2-8：时间戳、工具计数、TODO（15 vs 21 次迭代）、详细错误（替代方案 60%→95%）、系统状态。时间感三轴：紧迫度、坚持度、警觉度——光给读数几乎无效，要配“读数怎么用”的操作手册（+19 到 +49 个百分点）。设计哲学：人类可读、不微调即可叠加。

**2.7 压缩。** 动机不只长度：还有把“需思考才能得的结论”变成可检索知识。上下文腐化不等于溢出：装得下但找不到。Karpathy：记性差是特性，逼抽象。压缩发生在两次 API 之间，静态前缀不动；压 tool results 会废替换点之后的缓存，故宜接近阈值再批量压。实验 2-9 追踪 OpenAI 联合创始人：无压缩第五次溢出失败；上下文感知压缩把查询与已有信息纳入决策，token 可降 75% 以上。生产五层（对标 Claude Code）：工具结果预算与冻结替换、噪声直接删、API 层微压缩、归档式摘要、全量压缩。保留优先级：架构决策不得摘要；文件列表与验证状态、未解决 TODO 必须留；UUID、hash、URL 原样。**隔离优于压缩**：子 Agent 探索，主上下文只收几百 token 结论（Claude Code Task、Deep Research）。

**2.8 本章小结。** 眼睛决定上限；前缀稳定、动态置尾；Skills 与状态栏是同一套末尾元信息通道；压缩与隔离补注意力的“提炼”半边。

**本章要点**：

1. 上下文质量常比模型档位更能决定 Agent 上限。
2. KV Cache / Prompt Cache 把“前缀字节级稳定”变成架构约束。
3. 系统提示要流程化、规则可执行；提示注入是上下文安全主威胁。
4. Skills 渐进披露 + 状态栏蒸馏，解决膨胀与“检索而不归纳”。
5. 压缩为信息密度服务；能隔离进子 Agent 时，隔离优于事后压缩。

### 第3章 用户记忆和知识库

**本章主旨**：第二章管单次会话；本章把知识做成跨会话持久化。用户记忆是个体尺度（懂你），知识库是群体尺度（领域专家），共用检索、压缩，也共用冲突、过期、检不准。两条线在**双层记忆架构**汇合：Advanced JSON Cards 常驻概览 + 上下文感知检索按需取细节。

**内容展开**：

**3.1 用户记忆。** 本质是用额外 LLM 调用从对话抽出可预测用户的模型：选择性、抽象化、结构化。评估先立标尺：LoCoMo 等基准上归纳八项能力；再压成三层——基础回忆、多会话检索（两辆车预约保养要问清哪辆）、主动服务（护照将过期预警、报税季拼税务文件）。实验 3-1 每层 20 用例、LLM-as-judge。

层次：轨迹（只增不改的流水账）vs 用户长期记忆（跨会话档案）vs 可选业务状态。四种格式：Simple Notes（原子、耗时固定、丢关联）、Enhanced Notes（叙事完整、难更新难检索）、JSON Cards（三层键值、刚性分类）、Advanced JSON Cards（backstory/person/relationship 消歧，成本高）。实践按关键少量 vs 大量非关键混合。进阶：User as Code 把用户建成带类型的 Python，聚合统计正确率可近 99%（检索式文本记忆聚合仅 6%–43%）；User as Engram 写入哈希 N-gram 槽，靠预训练门控“存了也会用”；多模态可存难言说的感知。认知对应情景/语义/程序记忆。框架：Mem0 偏事实条目；Memobase 画像+事件、缓冲批处理。压缩：重要性评分、聚类摘要、抽象成规律、冲突版本化——与第二章窗口压缩不同层，触发机制见第八章。隐私：实验 3-3 本地小模型日志脱敏，召回 95% 以上，敏感日志不上云。

**3.2 RAG 基础。** 检索器 + 生成器补训练截止日期与私有知识。分块划定单元。稠密嵌入语义近邻；稀疏 BM25 精确词（k1 饱和、b 长度归一）；学习型稀疏如 SPLADE。混合：并行召回 → 归一化加权或 RRF（得分是各路排名平滑倒数之和，k 常 60）→ 跨编码器重排前 N。指标包括 recall@k。多模态提取图表与版式。

**3.3 超越扁平文本。** RAPTOR 树状摘要适合由宏观钻细节；GraphRAG 实体关系适合“A 与 B 什么关系”，但三元组会丢掉条件与时间逻辑，故自然语言正文 + 结构化索引分层。文件系统范式（OpenViking）：L0/L1/L2 按需加载，Markdown + 维基式链接，否则知识变孤岛。治理：过期与增量（HNSW 可插、ANNOY 需重建）、失效内容带版本、共享库权限。智能体化 RAG：Agent 决定何时检索、检索什么，从管道变迭代探索。上下文感知检索给每块加前缀摘要，解决“好的，就订这个吧”脱离机票上下文的问题。数据集知识发现（实验 3-13 CAIL2018）：自下而上抽因子、聚类案件原型，Agent 按重要性提问再对照原型给刑期区间——从检索到发现。

**本章小结。** 最高层主动服务必须同时握概览与细节；只常驻会丢细节，只检索看不见跨会话暗线。

**本章要点**：

1. 记忆评估三层：回忆 → 多会话消歧 → 主动服务。
2. 存储格式在简单性与表达力之间权衡，关键实体用 Advanced JSON Cards。
3. RAG 栈：分块、稠密、稀疏、融合、重排；混合覆盖多数“找片段”查询。
4. 结构化索引与文件系统是升级项，不是默认必上。
5. 双层架构是用户记忆与知识库的交汇，也是主动服务的工程路径。

### 第4章 工具

**本章主旨**：工具是大脑连接数字世界的手脚。本章回答两类挑战：工具爆炸时如何选、如何发现（创造留第八章）；以及如何在同步 LLM 训练假设下做事件驱动异步。五类工具 + 通用设计原则 + MCP 生态 + 感知/执行/协作深挖 + 异步打断工程。

**内容展开**：

**4.1 分类。** 调用方向与作用对象：感知/执行/协作由 Agent 主动；事件触发是注册后外部唤醒；用户沟通是主动传信息。协作动机：并行，或换模型/工具/提示/上下文。无事件工具则只能等人开口。

**4.2 通用原则。** 形态二选一：专用代码工具 vs Skill+通用执行器——看参数复杂度、变更频率、模型能力。粒度：功能相似且参数形态接近则整合（多格式 extract → 一个 read_document）；OCR 与视频提取不宜硬并。通用优于专用，除非安全、权限、平台差异（grep）。描述核心是“何时用”和“做不到什么”；参数给例子（E.164、RFC3339）；返回值与耗时写清；1–5 个真实调用示例可把准确率从约 72% 提到约 90%。选错工具先查描述再怪模型。参数保真：禁止静默转换（弯引号变直引号导致“看见却匹配不到”）。演进到动态发现、描述外置（第三代与 MCP 工具膨胀有关）。

**4.3 MCP。** 2024 年底开放标准，客户端-服务器，JSON Schema 工具，stdio 或 Streamable HTTP，原语分工具/资源/提示。一次开发多客户端可用。局限：请求-响应为主，跨会话唤醒要在协议上自建事件层。5 个 MCP 服务器即可约 5.5 万 token；Cursor 把描述放文件夹按需查，MCP 相关任务 token 降 46.9%。层次分类 + 按需检索（Anthropic：Opus 4 工具基准 49%→74%）。Skills 把选择过载变成知识检索。信任风险：描述投毒、供应链、同名遮蔽、凭证；审查 description、锁版本、最小权限；Sidecar 看结构化调用。致命三要素见第五章。

**4.4 感知。** 输出超阈值做上下文感知压缩；搜索返回结构化列表+分页；read 要 offset/limit，截断必须显式。

**4.5 执行。** 安全是核心。Sidecar 用轻量模型分类结构化工具调用，与提议者-审核者不同：后者审开放思考需能力相近，前者是分类。拒绝熔断回退人工。写文件后自动 linter。长输出头尾+落盘。沙盒：venv 不是沙盒；OS 级限制 → 容器 → microVM。可观测性、幂等与预检-确认（转账/发邮件不可盲目重试）。

**4.6 协作。** 创建、发消息、取消子 Agent；大搜索隔离进子上下文（呼应 2.7.7）。

**4.7 异步。** 同步像单柜台；真实秘书要并行、优先级、打断恢复。矛盾：训练假设“工具调用的下一条必须是工具结果”，部署要求随时打断。OpenClaw：Hooks / Cron / Heartbeat 看起来自主，但对第三方事件仍偏时间驱动；PineClaw Channel 把电话验证码等从分钟级轮询降到秒级推送。事件工具：定时器、后台命令监控、外部通道。虚拟身份与隔离环境支撑独立行动。工程五规则：立刻记 assistant；完成才记 tool result；打断时占位符配对；思考中打断丢弃当前思考；非打断进队列。占位符会诱发幻觉，故只在真正紧急时打断。工具接口应拆“发起”与完成事件。批量事件要用提示和状态栏防“只看最后一条”。深层矛盾：模型仍是同步生物，异步是 harness 模拟。

**4.8 本章小结。** 手脚质量 = 描述 + 粒度 + 安全闭环 + 事件模型；MCP 解决互操作不解选择过载与离线唤醒。

**本章要点**：

1. 五类工具按谁发起、作用于谁来设计，事件类改变 Agent 能否“自己动起来”。
2. 专用工具与 Skill+执行器按三维度选；描述写边界和例子比换模型更划算。
3. MCP 是插座标准，要配按需加载、审查与最小权限。
4. 执行工具默认危险：Sidecar、沙盒、幂等、预检-确认。
5. 异步是用占位符和启动/完成解耦，在同步 API 上模拟真实世界。

### 第5章 Coding Agent 与代码生成

**本章主旨**：开放任务通用 Agent 的内核是 **Coding Agent + 文件系统**。代码既是最高效的行动手段，也是元能力：思考、约束规则、多媒体、适配器、生成式 UI、自举。Harness 在编程场景特别强，因为测试、类型、Git 天然构成验证与纠正。

**内容展开**：

**5.1.1 基础能力。** 整理 TODO 这类任务只要列目录、读、编辑/写、命令行、内容搜索。七工具参考集：代码解释器、Bash、读、写、编辑、按文件名搜、按内容搜（解释器有时可与 Bash 合并）。协作/事件/沟通多由框架而非再添专用工具处理。代码是通用解题手段，不只写程序。

**5.1.2 Manus 到 OpenClaw。** Deep Research、Computer Use、Coding 融合时，几乎所有高效产出最终落到代码（办公文档格式、脚本、流程自动化固化）。Computer Use 更通用但更贵更慢更不稳。OpenClaw 用少量通用工具叠加浏览器与搜索。适用边界：强结构化、强 API 的窄任务不必强行 Coding 内核。

**5.1.3–5.1.5 Sessionless、致命三要素、沙盒。** 持久化的是文件/脚本/清单，不是不透明进程。Simon Willison 致命三要素：私有数据、不可信内容、对外通信——三者齐备即攻击闭环；持久记忆让攻击跨会话。沙盒选型呼应第四章隔离阶梯。

**5.1.6 流程。** 理想五段：项目文档化（缺文档就生成；CLAUDE.md、AGENTS.md 当项目级系统提示，对 KV Cache 友好）→ 需求澄清 → 设计文档等人审 → 编码测试闭环 → 自审与交付。现实产品按任务复杂度裁剪。远程友好团队往往更适合配 Agent：口头部落知识 Agent 读不到。

**5.1.7 Harness 在 Coding 中。** 测试套件、linter、类型系统是验证；权限分类是约束。数据层更彻底：把不变量下沉到应用层之下的 schema 与访问上下文，使模型写的处理逻辑即以受限主体运行——对照实验可达“声明不变量零违规”，代价约每次写入 2ms。

**5.1.8 技巧。** 流式下第一工具参数完整即可执行；失败级联中止声明了并发的调用。大文件按行号范围读并标注行号。终端输出头尾截断。状态栏注入当前目录、git 分支、未暂存变更。持久 shell 保留虚拟环境与工作目录。写入后立即 linter。

**5.1.9–5.1.10 搜索与编辑。** 搜索是感知；字符串替换比整文件覆盖更安全，参数必须保真。

**5.2 代码作为元能力。** （1）思考：约束求解解骑士无赖，弱模型代码辅助准确率可上 90%，强思考模型增益收窄——脚手架厚度随模型能力而变。（2）业务规则：自然语言给人解释，代码当守门员；航空取消政策把校验合并进执行，模型自报的期望字段是清单不是事实。（3）多媒体：提议者-审核者生成演示文稿/视频。（4）系统适配器：日志格式变了就重生解析器。（5）生成式 UI：声明式组件清单防任意脚本；HTML 活文档可交互演示；动态表单一次澄清级联问题；自然语言转 SQL 要权限边界。（6）自举：基于范例改 Agent 比从零生成更能继承最佳实践。

**5.3 本章小结。** Coding 成熟是因为软件工程基础设施就是 Harness。下一章用评估度量这些设计。

**本章要点**：

1. 开放任务通用 Agent 近似 Coding Agent + 文件系统 + 少量通用工具。
2. 七工具覆盖感知与执行；项目指令文件是最便宜的稳定前缀。
3. 致命三要素与数据层不变量，决定安全边界不在“提示里写别作恶”。
4. 代码把模糊规则变成可执行约束，并在弱模型上补逻辑正确性。
5. 生成式 UI 与自举把工具从“调用”推到“创造同类系统”。

### 第6章 Agent 的评估

**本章主旨**：没有度量就没有改进。评估对象是 **模型 + Harness 组合**，不是孤立模型。模型替换实验区分瓶颈在模型还是 Harness；消融定位 Harness 内部部件。评估体系的首要价值是：新模型发布后数小时内能决定是否切换。

**内容展开**：

**6.1 示例。** 客服退 3 天前订单、政策 7 天全额。Rubric 拆操作正确性、政策合规、信息完整性等 1–4 分，把轨迹变成可检查维度。

**6.2 环境。** 组成：任务、工具/模拟器、初始状态、验证器。工具调用型（客服政策基准一类）与人机交互型（手机/桌面世界）；仿真环境章末接到后训练。

**6.3 数据集。** 五挑战：明确 vs 开放（GAIA 目标清、路径开放）；真实 vs 可控（SWE-Bench Verified 500 题人工筛）；多样 vs 系统（AndroidWorld 能力标签+参数化）；成本 vs 覆盖；防泄漏（GAIA 独特附件、SWE-bench-Live 时间新鲜、动态参数、金丝雀标识）。描述要可机验；复杂度分层使失败能指向工具、规划或长序列。可验证性：字符串匹配、界面终态、启动日志自定义打印。

**6.4 指标。** 成功率之外还有步数、工具正确率、延迟、成本、合规；Rubric 补开放生成。

**6.5 自动评估。** 用大模型当评委要好 Rubric：可验证行为、幻觉一票否决。同源模型会把指标变成可钻的空子，用多家族评判。多模态评委覆盖语音合成/识别、界面、视频关键帧。配对比较做模型排名，比绝对分稳健。

**6.6 选型。** 公开榜不等于你的任务。新模型可能在简单题上更便宜更好，在多轮工具编排上反而掉几个点——确认超出噪声后再做差异化部署。还要测首 token 时间、输出速度、思考延迟、一周可用性与恢复时间、速率限制，以及输入/输出/缓存单价下的多轮任务成本（前缀缓存会大幅改写账单）。记忆系统要把嵌入、重排器、主模型当联合选择：更强嵌入可能让重排边际为零，更强主模型可能补检索不足。

**6.7 统计显著性。** 成功率服从二项，样本 100、成功率 70% 时标准误约 4.6%，区间往往宽到 ±9 个百分点；独立两次之差噪声更大。3 个点差分差常不够切换。同批任务默认配对检验，扣除题目难度这一共同噪声。温度、工具抖动要求多次随机种子报均值与波动。并行验证多条假设时假阳性会累积，要收紧门槛或独立复跑。预期收益只有两三个点而评估集只有几十题时，应先扩集，而不是继续改 Agent。

**6.8 可观测性。** 轨迹、工具、token、错误进入追踪，支撑发现问题和对照实验。

**6.9 从报告到改进。** 观察→假设→实验→验证。AndroidWorld 例子：从失败轨迹映射能力标签，表层改提示、中层改管道、深层改动作空间；按成本收益部署。

**6.10 内部评估。** OpenClaw 式：启动早期注入消融总开关；对照实验要区分机制指标与目标指标并设护栏（计划变短是机制，会话成本才是目标）；编译时/运行时双层特性开关；提示词按版本做回归；隐私感知分析。

**6.11 仿真。** 考场变训练场。保真度与算力权衡；领域随机化缩小仿真到现实的鸿沟。接到第七章训练改造。

**6.12 本章小结。** 闭环：环境→数据集→自动评委→分析→改系统→更新集。评估即 Harness 的“验证”功能系统化。

**本章要点**：

1. 测的是模型加 Harness；换模型与消融回答不同问题。
2. 数据集质量（可复现、防泄漏、可分层诊断）决定评估是否测到真能力。
3. 结构化评分标准加多源评委降低钻空子；统计显著性决定能不能换模型。
4. 生产要把消融、对照实验、特性开关、提示版本当成一等基础设施。
5. 仿真连接评估与后训练，随机化决定能不能迁到真环境。

### 第7章 模型后训练

**本章主旨**（含书中标明的**可选阅读**）：优化公式里的 LLM。三阶段炼成：预训练预测下一词、监督微调固化协议、强化学习试错泛化。两条主线：**SFT 记忆、RL 泛化**；**数据与环境比算法更重要**。应用开发者可跳过 7.2、7.3 原理，仍须抓住决策框架。

**内容展开**：

**7.1 三阶段全景。** 预训练读万卷书；SFT 手把手标准解法（只在回答上算损失）；RL 下场做题。必须先 SFT 后 RL：没有稳定格式，奖励无法计算。表对比数据、目标、代价。

**7.2 从经典 RL 到现代 Agent［可选阅读］。** 马尔可夫决策过程、封闭动作空间、Q 学习与贝尔曼方程。现代 LLM Agent 动作空间开放且含内部思考，算法、样本效率、泛化与棋类/机器人范式分野。

**7.3 预训练基础［可选阅读］。** 扩展实验：续训注入新语言要用混合数据防灾难遗忘；要记大量新领域事实靠继续预训练而非 SFT。预算紧时算法与架构创新往往比纯堆规模更划算。预训练给的是描述性知识，指令遵循靠 SFT。

**7.4 SFT。** 价值在固化协议（风格、工具 JSON、思考模板），不在灌事实。实验：语音风格协议、多语言思考（激活预训练跨语言空间）、提示蒸馏、工具调用格式。过拟合与分布外崩溃是代价。

**7.5 何时 SFT / RL。** 测试分布接近训练、要稳格式 → SFT 往往够；要分布外、要探索新策略 → RL。RL 成本常为 SFT 的数十到上百倍。

**7.6–7.8。** 单轮 RL 对照记忆与泛化。RLHF：人类偏好 → 奖励模型。算法：REINFORCE 方差大；PPO 裁剪加价值网络；GRPO 组内相对优势、无价值网络但信用分配粗。奖励来源（规则验证器 vs 奖励模型）与优化算法是两件事。

**7.9 数据与环境。** 仿真场地保真与数据质量决定成败；算法你会用即可。

**7.10 多轮。** 信用分配、部分可观测、长依赖。过程奖励密、有偏见；结果奖励自由、难训。折扣因子在短任务常取 1。GRPO 轨迹级优势均摊到所有 token，长程任务 PPO 仍有价值。验证路径惩罚：奖励结果、惩罚错误路径，部分奖励救全败组。导航实验：规则/视觉分布外上 RL 升、SFT 崩；过程奖励逐步给正负分。机器人操作实验仅用成败二元奖励，极少示范冷启动后仍可大幅拉升。

**7.11 RL 学工具调用。** 把合法调用与恢复写进策略，弱模型尤其需要。

**7.12 样本效率。** 在线蒸馏兼得 SFT 密度与 RL 在线。时间感：稀疏结果奖励学不会节奏，逐 token 稠密信号才行（呼应第二章操作手册）。

**7.13 图景与坑。** 常见失败包括过训、价值崩溃、低估 RL 成本、脏数据。与检索/上下文学习协同：事实外接知识库，行为后训练内化，上下文示例探路。

**7.14 本章小结。** SFT 与 RL 是先后不是二选一；当前瓶颈常是样本效率，要把环境里被浪费的信号变成可学信号。

**本章要点**：

1. 能力流水线：预训练 → SFT → RL，顺序不可反。
2. SFT 记示范，RL 学可迁移策略，可用分布外实验测量。
3. 环境和数据质量通常比换具体算法品牌更决定成败。
4. 多轮任务要显式处理信用分配；过程/结果奖励是探索与可学性的权衡。
5. 后训练、检索、上下文示例是三个旋钮：事实不宜硬塞进 SFT。

### 第8章 Agent 的自我进化

**本章主旨**：不改权重如何持续变强。自我进化即外部化学习：从经验沉淀知识，以及发现/创造工具。后训练让模型更聪明，本章让 Agent 更能干。无限上下文也不会自动学习——注意力检索而不归纳，越长越腐化。

**内容展开**：

**8.1–8.2。** 与一、二、三、七章三种范式对照。本章补的是跨会话的策略、流程、失败教训与新工具，不是“用户是谁”（那是第三章）。反面：退款探索 15 分钟，下次从头再来。哲学：任务后用额外算力总结进可检索外部系统。

**8.3 从经验中学习。** 策略摘要；工作流录制（把成功轨迹编成带验证的状态机）；失败：错误模式库、负面规则、用自然语言反思写入情景记忆。Skills / 能创造 Skill 的元能力 / 项目指南文件：Agent 自己造操作手册。睡眠学习：离线整合用户记忆（可读的 Markdown 记忆文件等），何时整理、谁整理是工程问题。系统提示自动优化：从边界案例提炼禁则。长任务跨会话：进度用结构化文件加版本库，崩溃从文件系统续跑。

**8.4 主动工具发现。** 全量说明书注入在上千工具时失效；一次性语义预筛看不到后续工具链。主动声明缺口再注入，在约两千八百个工具上可省约 98% token。动态加载须把定义追加末尾保前缀；合法集合仍受接口参数约束。Skills 把发现变成按需查阅，工程更轻。

**8.5 从使用者到创造者。** 预定义集覆盖不了长尾。网上找库、写新工具、注册。Voyager 在沙盒游戏里持续学技能库。三层积累：轨迹经验、Skill 文档、可执行工具。安全边界：生成工具仍受沙盒与权限约束，不能自我放开致命三要素。

**8.6 本章小结。** 评估自我进化要测发现、创造、复用，任务描述不可剧透工具名。下一章离开纯文本对话框。

**本章要点**：

1. 学习必须被设计：堆原始轨迹不会自动变成规律。
2. 经验出口包括摘要、工作流、反思、Skills、提示词规则、睡眠整理。
3. 工具过多时主动发现或 Skills 优于平铺说明书。
4. 创造工具是能力边界的最终扩展，必须留在隔离执行里。
5. 外部化学习与后训练互补：一个改文件与库，一个改参数。

### 第9章 多模态与实时交互

**本章主旨**：静态看图读 PDF 已融入感知工具；本章专攻**实时性把多模态变难**的三场景：语音、Computer Use、机器人。共同方向：串行流水线 → 端到端，并处理“秒级思考 vs 毫秒级响应”。生成式多媒体只当普通工具，不在主线。

**内容展开**：

**9.1–9.2 语音与三种范式。** 说话约四倍于打字；口述指挥编程即引言中的 whisper coding。三分法：级联识别-语言模型-合成；全模态单模型仍轮流说话、靠语音活动检测；全双工边听边说，取消轮次。生产中三种长期并存。第二条主线：交互与深度思考解耦。

**9.3 级联。** 活动检测、转写、生成、合成接力，信息丢失、延迟叠。全链路流式与流式语音感知可把切轮从静音猜改到语义。

**9.4 Omni 与全双工。** 全模态保留韵律情感，仍有轮次误判；后续工作把思考内化进音频模型。全双工并行建模用户与自身声音，延迟可到约 200ms。交互模型以约 200ms 微轮次交织多模态，主张交互性应内建于模型。GPT-Live 每秒多次决定说/听/停/打断/调工具，并把难题委派后台强模型。替代语音活动检测叙事的终点：打断不再是特殊事件。

**9.5 思考架构。** 方案一快慢简单并行；方案二前台交互、后台军师（因推理模型迭代快、不宜塞进同一实时模型，成为产品主流）；方案三边想边说内化。快慢接口除文本外可传隐向量，图形界面与机器人同样会问“何时请慢军师”。

**9.6 更像人的合成。** 执行层韵律、附和、停顿，服务对话节奏而非念稿。

**9.7 Computer Use。** 截图→思考→鼠标键盘。动作空间含点击拖拽、打字、组合键、截图、等待；另配终端与字符串编辑。视觉定位：画面编号选择题 vs 纯坐标；网页上用文档对象与无障碍树更稳。动画与声音要求超越静帧。移动端生态壁垒大于技术。实时性：动作间隔常 2–5 秒，远慢于人，是未解核心。

**9.8 机器人。** 硬件往往不是瓶颈。双层：视觉语言模型规划 + 视觉-语言-动作控制。长程规划走向专用具身思考模型。从演示到跨身体泛化。仿真到现实：视觉与物理域随机化、相机对齐；分布外物体成功率仍掉。

**9.9 本章小结。** 三场景卡在延迟与多模态；语音路线最清晰，界面与机器人仍重。

**本章要点**：

1. 本章边界是实时流，不是静态视觉理解。
2. 语音三代：级联 → 轮次全模态 → 全双工；快慢解耦是产品主流。
3. 图形界面自动化的关键是定位与动作空间，实时仍远落后人类。
4. 机器人用规划/控制分离和域随机化过仿真鸿沟。
5. “何时调用慢思考”是跨语音、界面、具身的同一架构题。

### 第10章 多 Agent 协作

**本章主旨**：多 Agent 不只补窗口和专长，还可能涌现高于个体的集体智能。工程上先选**上下文是否共享**和**协作拓扑**；只有引入单 Agent 生成时拿不到的**新信息**（测试执行、截图、外部工具），多 Agent 才真正优于单 Agent。

**内容展开**：

**10.1 分类。** 共享上下文：换提示与工具即换角色，记忆全留，信息不丢但易膨胀。不共享：独立轨迹，靠工具参数、共享文件系统、消息总线显式传。选择：预期上下文超窗口约一半则不共享；零损耗是硬约束则共享；常见阶段切换——先共享，饱和后移交。拓扑：对等迭代、管理者编排、去中心化移交。共享时拓扑常退化为角色序列。

**10.2 何时优于单 Agent。** 同一模型自我审查、纯文本辩论通常无新信息，等算力下不优于单 Agent。审查者跑测试、看渲染、调外部验证则显著提升。学术“单 Agent 够了”与工程爱拆多 Agent 的矛盾，用这条判据可解。

**10.3 共享上下文。** 多阶段：需求→实现→审查，用特定工具触发切换，发现问题时可退回修改。跨领域：分诊角色在检索/编程/数据分析/写作间移交，完整历史天然保留。

**10.4 不共享。** 文件系统是 Agent 眼中的大对象通道。通信与控制要契约化。对等：起草-批注循环。管理者：最强模型给规划者（与第四章“审者能力须相近”不冲突——那是审查，这是规划）。书籍翻译：术语表、多实例章节翻译、全文审校，管理者只留计划与文件索引。去中心化递进：有的系统控制流其实是标准作业流水线，解耦在标准化文档；有的是共享记录加中心选择器；对等移交网络才把路由分散到每个 Agent。移交包：任务与验收、已确认事实、文件路径引用，不传全量试错轨迹。跨组织协议用能力名片与任务状态机。

**10.5 失败模式。** 共享文件并发冲突；错误级联放大——隔离与契约不能省。

**10.6 Agent 社会。** 斯坦福小镇：记忆流+反思+规划，派对邀请扩散为涌现社交。大规模 Agent 社交网络、经营竞技场、人机交易市场。狼人杀：信息不对称下策略，法官按角色过滤上下文。此处反思更新即时目标，与第八章任务后更新长期能力不同。

**10.7 本章小结。** 多 Agent 是公式的系统层表达：隔离上下文、Agent 互为工具、用评估判有无新信息。

**本章要点**：

1. 先问有没有新信息，再问要不要多个 Agent。
2. 共享 vs 不共享决定信息损耗与并行/成本。
3. 不共享时必须设计移交包与拓扑；规划者应拿最强模型。
4. 失败模式来自并发与错误传播，不是“再加一个 Agent”能自动修好。
5. 社会与经济模拟展示涌现，不等于生产编排的默认形态。

### 后记：回到 Agent = LLM + 上下文 + 工具

**本章主旨**：十章没有走出开篇公式。后记用“两朵乌云”标出公式尚未被现有工程抹平的缺口，并用模型与 Agent 共同演进的飞轮说明 harness 与权重如何互相喂养。

**内容展开**：

**收束映射。** 第一章给三层理解与编排光谱。上下文支柱：第二、三章。工具支柱：第四、五章（代码是能创造工具的工具）。模型支柱：第六、七章（一个度量、一个放大）。第八章不改权重的进化；第九章感知行动出文本；第十章不是新公式——共享与否是“隔离优于压缩”的系统版，互为工具来自第四章，新信息判据来自第六章。

**第一朵乌云：流式实时交互。** 今日仍多是一轮一轮：说完→想整段→一次吐出。真世界会打断、画面在变、邮件在到。两条路并行：架构快慢分离（实时与智能近乎正交）；以及把生成速度做快（书中举单节点超大模型每秒过千 token、以及把模型固化进芯片后极低响应的例子）。足够快时，轮次等待与“边想边说”的体验差被抹平。

**第二朵乌云：从成败中持续学习。** 模型像记性极好却上岗后不再成长的天才。小世界假设：够大的模型一次蒸馏行业数据即可，瓶颈在数据开放（编程最强因为开源最多）。大世界假设：具体公司规范、团队口味、客户脾气不在语料里且一直在变，必须上岗后学——记忆、自我进化、用 AI 做科学都在这条线上。最强能力终将是学习与适应，不是背诵。

**共同演进。** Harness 里多层压缩、上千次才熔断的重试、默认不安全的权限，记录的是模型此刻做不稳之处；下一代模型内化后对应代码可删，而内化信号正来自 Agent 在真业务里趟过的坑。不换模型只改 harness，终端基准可从约 53% 到约 67%——杠杆大，正因为模型还没走到那一步。造模型要把反馈飞轮转起来；造应用要把 harness 当争取时间的杠杆，把长久壁垒放在数据、渠道、信任、网络效应，以及人机必须共担的复杂场景。

**本章要点**：

1. 全书是公式的展开，不是公式之外的新理论。
2. 两朵乌云：实时流式交互；上岗后从环境反馈中学习。
3. 小世界 vs 大世界决定你押“一次训完”还是押记忆与进化。
4. 模型与 Agent 是飞轮两端，不是上下游交付关系。
5. 应用层 harness 优势会被模型内化削平，需同步构筑非纯技术壁垒。

## 全书总述

**这本书主要讲了什么**：

作者面对的问题是：Demo 级 Agent 与能打电话谈钱、改代码到测试通过、在语音里边听边说的产品之间，差的不是又一个框架名词，而是一套可迁移的设计原则。答案被收成一句：**Agent = LLM + 上下文 + 工具**。LLM 决定如何选下一步（策略）；上下文决定此刻能看见什么（观察）；工具决定能对世界做什么（动作）。最小系统三件套就能转 ReAct 循环；要在生产里长期可靠，还要在上下文与工具外围加上约束、验证、纠正——这圈外壳叫 Harness。全书十章按“先认公式，再把三支柱做厚，再把支柱组合进进化、实时与多 Agent”推进。

论证顺序是：引言用 Pine 与实战营说明原则来自长流程高风险，而不是等 Skill、harness 一词流行。第一章把公式对齐到产品表、五类工具、三种学习、ReAct 轨迹和编排光谱（提示 → 工作流 → 自主）。第二、三章专做“眼睛”：先证明消息列表、缓存前缀、Skills 与状态栏、压缩/隔离如何决定单次会话质量，再把眼睛延伸到跨会话——用户记忆三层能力与检索/结构化索引/双层架构。第四、五章专做“手脚”：工具描述与 MCP、感知执行协作与异步事件；然后论证开放任务的通用形态往往是 Coding Agent + 文件系统，代码同时是最高效工具和元能力。第六、七章转向“大脑”：评估让改进可证伪，后训练把稳定协议（SFT）与可迁移策略（RL）写入权重，并反复强调环境和数据重于算法品牌。第八章在不改权重的前提下把经验写成 Skill、工作流与新工具。第九章让观察与动作离开纯文本，用快慢模型对抗实时延迟。第十章在系统层复制同一公式：是否共享上下文、Agent 能否给同伴新信息、失败如何隔离。后记指出公式尚未覆盖的两朵乌云——流式实时、上岗后继续学习——并说明 harness 与模型训练是同一飞轮。

读者若只记一条操作定义：每次 LLM 调用看见的消息列表（加上工具定义）就是眼睛；模型返回的工具调用或文本就是下一步；框架执行工具、追加结果、循环直到退出条件——其余章节都是在问：这个列表里该放什么、什么不能改、放不下时压谁、跨会话存哪、工具如何描述与隔离、如何证明改动真的好了、何时该改权重何时该写文件。

**部分与部分如何衔接**：

基础篇（引言+第一章）提供术语和最小循环。支柱篇里上下文（2–3）必须先于工具（4–5）读懂，因为工具定义占静态前缀、工具结果撑爆轨迹、协议描述本身是注入面。模型篇（6–7）依赖前五章已经能跑的 Agent：没有可复现环境与轨迹，评估和强化学习没有场地。进阶篇（8–10）分别调节公式的三个旋钮而不引入第四个本质组件：第八章外部化眼睛与手脚的记忆；第九章把观察/动作换成音频、像素、关节；第十章把一次循环复制成多条，用隔离与新信息判据决定复制是否值得。后记把十章折回公式，并指向实时与终身学习两条未完成线。

**读完应记住的主线**：

1. Agent = LLM + 上下文 + 工具；生产上再加约束、验证、纠正（Harness）。
2. 上下文 = 静态前缀 + 轨迹；前缀字节级稳定是缓存与成本的架构约束。
3. 注意力擅长检索、不擅长一次前向归纳——状态栏、压缩、记忆整理、自我进化都在补“提炼”。
4. 工具要通用、描述要写边界；MCP 解互操作，Skills/发现解选择过载；执行默认按危险品设计。
5. 开放任务通用 Agent 的内核常是 Coding + 文件系统；软件工程设施就是现成 Harness。
6. 评估测模型加 Harness；无新信息的多 Agent 通常不值得；切换模型看统计显著性。
7. SFT 固化协议，RL 求泛化；事实放检索，行为可后训练；不改权重仍可通过外部化变强。
8. 实时与智能常常拆开；模型与 Agent 共同演进，今日 harness 的补丁可能成为明日权重里的能力。
